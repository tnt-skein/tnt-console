# Консольные команды

`tnt-console` — консольные команды приложения: команда объявляется
таблицей, командную строку разбирает рок `argparse`, а код выхода говорит,
чем кончилось, — удача, отказ, неверный вызов или поломка.

```lua
local console = require('tnt.console')

local app = console.new({ name = 'console.lua', description = 'Команды приложения' })

app:command('greet', {
    description = 'Поздороваться',
    arguments = { { name = 'who', description = 'с кем' } },
    handler = function(input, out)
        out:line('здравствуй, %s', input.who)
    end,
})

app:main()   -- tarantool console.lua greet мир  →  «здравствуй, мир», код 0
```

Команду, которой нужен живой узел, выполняет узел, а сценарий оператора
только повторяет её вывод и код выхода:

```lua
-- на узле: функция для lua_call
rawset(_G, 'app_command', function(argv)
    return app:reply(argv)
end)

-- у оператора: console.lua
console.remote({ uri = '127.0.0.1:3301', user = 'operator', password = secret, call = 'app_command' }):main()
```

Своего разбора аргументов командной строки у пакета нет: разбирает рок
`argparse` 0.7.2. Пакет — фасад **поверх** рока: собирает ему разбор
из объявления, забирает итог и закрывает то, чего у рока нет. Всё ниже
сверено на Tarantool 3.8.0, Linux x86_64.

Выпуск рока закреплён (`argparse == 0.7.2-1`). На сервере роков
Tarantool, который `tt rocks` берёт по умолчанию, выпуски кончаются
на 0.6.0, поэтому rockspec закреплённого выпуска лежит копией
с luarocks.org на том же сервере, что и пакет, и рок ставится вместе
с пакетом одной командой:

```sh
tt rocks install tnt-console --server=https://tnt-skein.github.io/rocks
```

## Зачем пакет

1. **Рок ведёт себя как самостоятельная программа.** Ключ `--help` рока
   печатает справку и зовёт `os.exit(0)`, а `parse` на ошибке разбора —
   `os.exit(1)`. Команда, позванная из кода узла, уронила бы узел. Здесь
   справка и отказ разбора — итог вызова, и та же команда зовётся из кода
   (`call`) с выводом в строках итога.
2. **Слова по-английски.** «missing argument», «unknown option», «Usage:»,
   «(default: …)» зашиты в код рока. Здесь отказы, справка и строка вызова
   — по-русски.
3. **Код выхода различает, чем кончилось.** Рок кончает неверный вызов
   кодом 1 — тем же, каким обычно кончается отказ. Здесь отказ — «так
   бывает», поломка — «чини код», а неверный вызов — ни то ни другое:
   до обработчика дело не дошло. Сценарий, позвавший команду, видит это
   по коду, не разбирая текст.
4. **Вывод не знает, куда уходит.** Обработчик пишет строки, таблицу
   и значения в вывод, а в потоки процесса он уйдёт или в итог вызова
   из кода, решает тот, кто команду позвал. Таблица выравнивается
   по знакам, а не по байтам: `string.format('%-10s')` сдвигает столбец
   с кириллицей. Значение показывает `tnt-debug` — без броска на функции
   и с тайнами под отметкой.
5. **Команда отдельным процессом.** Долгая работа без уступки в файбере
   узла держит узел целиком, а срез файбера рвёт её через секунду.
   `execute` запускает команду тем же Tarantool отдельным процессом через
   `tnt-process`: у запуска есть срок, просроченный процесс убит вместе
   с группой, вывод и код приходят итогом.
6. **Команда на узле с настоящим кодом выхода.** Команде, которой нужны
   спейсы и службы живого узла, консоль узла не годится: ответ она
   заворачивает в YAML, а отказ и бросок кончаются кодом 0 — сценарий
   не отличит удачу от отказа. Узел публикует функцию на `reply`,
   а `remote` зовёт её по iproto и кончается тем кодом, которым команда
   кончилась на узле. Учётке оператора хватает права на одну функцию
   (`lua_call`), права на `eval` для всего ей не нужно.

Зависимости: рок [`argparse`](https://github.com/luarocks/argparse)
(разбор), [`tnt-process`](https://github.com/tnt-skein/tnt-process)
(процесс и отказ вызова), [`tnt-debug`](https://github.com/tnt-skein/tnt-debug)
(показ значения), [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(проверки аргументов) и [`tnt-external`](https://github.com/tnt-skein/tnt-external)
(подмена вывода, аргументов процесса, выхода и клиента iproto `net.box`
в проверках). Состояния у пакета нет, кроме объявленных команд.

## Как пользоваться

Приложение командной строки — сценарий, который объявляет команды
и зовёт `main`:

```lua
-- console.lua
local console = require('tnt.console')

local app = console.new({ name = 'console.lua', description = 'Команды приложения' })

app:command('cache:clear', {
    description = 'Забыть записи кэша\nБез ключа --force спрашивает подтверждение словом.',
    arguments = {
        { name = 'store', description = 'хранилище', optional = true, default = 'default' },
    },
    options = {
        { name = 'force', short = 'f', description = 'без слова подтверждения', flag = true },
        { name = 'older', description = 'старше, с', type = 'number' },
        { name = 'tag', description = 'метка; можно несколько раз', many = true },
    },
    handler = function(input, out)
        if not input.force then
            return nil, 'нужен ключ --force: записи забываются насовсем'
        end

        out:line('хранилище %s: забыто, меток %d', input.store, #input.tag)
    end,
})

app:main()
```

```sh
$ tarantool console.lua cache:clear sessions -f --tag a --tag b
хранилище sessions: забыто, меток 2
$ echo $?
0
$ tarantool console.lua cache:clear
нужен ключ --force: записи забываются насовсем
$ echo $?
1
$ tarantool console.lua cache:clear --older soon
Вызов: console.lua cache:clear [-h] [-f] [--older <older>]
       [--tag <tag>] [<store>]

Ошибка: ключ «--older» — число, а не «soon»
$ echo $?
2
```

| Вызов | Что делает |
|---|---|
| `console.new({ name, description })` | приложение командной строки (`TntConsoleApp`) |
| `app:command(name, spec)` | объявляет команду; отдаёт приложение |
| `app:main()` | разбирает аргументы процесса, выполняет команду и кончает процесс её кодом |
| `app:run(argv)` | выполняет командную строку, вывод — в потоки процесса; отдаёт код выхода |
| `app:call(argv)` | выполняет командную строку из кода; итог `{ code = 0, stdout, stderr }` либо отказ |
| `app:reply(argv)` | то же, но итог одной таблицей `{ code, stdout, stderr }` при любом коде — тело функции узла |
| `console.execute(script, argv, opts)` | команда отдельным процессом Tarantool: итог либо отказ `tnt-process` |
| `console.remote(opts)` | команда на узле (`TntConsoleRemote`): `run(argv)` отдаёт код, `main()` кончает им процесс |
| `console.OK` … `console.BROKEN` | коды выхода: 0, 1, 2, 70 |
| `console.UNAVAILABLE` | код выхода 69: узел не ответил |

### Объявление команды

```lua
app:command(name, {
    description = 'Что делает команда',   -- первая строка — в списке команд
    arguments = { … },                    -- позиционные, по порядку
    options = { … },                      -- ключи
    handler = function(input, out) … end,
})
```

Имя команды — строчные латинские буквы, цифры, `:`, `_` и `-`, с буквы:
`migrate`, `cache:clear`, `make-seed`. Описание обязательно — у команды,
у аргумента и у ключа: справка без него бесполезна.

**Аргумент** — позиционное значение:

| Поле | Что задаёт |
|---|---|
| `name` | имя и поле входа: `[a-z][a-z0-9_]*` |
| `description` | что это — в справке |
| `optional` | может не прийти |
| `many` | список значений: с `optional` — ноль и больше, без — одно и больше |
| `default` | значение, когда не пришло; только у необязательного |
| `type` | `string` (по умолчанию), `number` либо `integer` |
| `choices` | допустимые значения списком строк |

**Ключ** — значение по имени:

| Поле | Что задаёт |
|---|---|
| `name` | как его набирают без дефисов впереди: `dry-run` для `--dry-run`; `[a-z][a-z0-9-]*` |
| `short` | одна буква: `f` для `-f` |
| `description` | что это — в справке |
| `flag` | ключ без значения: во входе `true`, если пришёл, иначе `false` |
| `required` | обязателен |
| `many` | повторяется: во входе список, без ключа — пустой список |
| `default`, `type`, `choices` | как у аргумента |

Обработчик получает **вход** — таблицу значений по полям — и **вывод**.
Поле ключа — его имя с дефисом, заменённым подчёркиванием: `--dry-run` →
`input.dry_run`. Значение из командной строки — строка, а у `number`
и `integer` — число; умолчание приходит тем же родом, что набранное
(`default = 5` у строкового элемента — `'5'`), и проходит те же проверки.
`number` отвергает `nan` и бесконечность, которые `tonumber` читает
молча, `integer` — ещё и дробь:

```lua
app:call({ 'cache:clear', '--older', 'inf' })
--> nil, err.stderr: … Ошибка: ключ «--older» — число, а не «inf»
```

`--help` и `-h` есть у приложения и у каждой команды сами: имя `help`
и буква `h` заняты. Неверное объявление — бросок на строке объявления,
а не отказ у оператора, впервые набравшего команду:

```lua
app:command('probe', {
    description = 'Прочитать файл',
    arguments = {
        { name = 'file', description = 'файл', optional = true },
        { name = 'directory', description = 'каталог' },
    },
    handler = function() end,
})
--> команда probe: аргументы[2]: обязательный аргумент не ставится после необязательного
```

Прочие отказы объявления: имя не по образцу, поле описания с опечаткой,
поле входа или буква уже заняты, у флага — `type`, `default`, `choices`,
`many` или `required`, у списка значений — умолчание, у обязательного
ключа — умолчание, аргумент после списка значений, умолчание, которое
не проходит `type` или `choices`.

### Код выхода

| Код | Имя | Когда |
|---|---|---|
| 0 | `console.OK` | команда сделала своё; обработчик ничего не вернул, вернул `true` либо 0 |
| 1 | `console.FAILURE` | отказ: обработчик вернул `nil, err` либо `false`; причина — в поток ошибок |
| 2 | `console.USAGE` | неверный вызов: нет такой команды, не хватает аргумента, незнакомый ключ |
| 69 | `console.UNAVAILABLE` | команда на узле: узел не ответил — нет связи, права, функции, срок вышел |
| 70 | `console.BROKEN` | поломка: обработчик бросил либо вернул код не из 0…255; команда на узле — узел ответил не итогом команды |

Обработчик, вернувший число, задаёт код сам — у проверки «нашла» тоже
ответ, а не отказ:

```lua
app:command('diagnose', {
    description = 'Назвать испорченные файлы',
    handler = function(_, out)
        local broken = { '00000000000000000080.xlog' }

        out:line('испорченных: %d', #broken)

        return #broken > 0 and console.FAILURE or console.OK
    end,
})
```

Два — код неверного вызова у утилит оболочки, и сценарий отличает его
от отказа самой команды. Семьдесят — «внутренняя ошибка программы»
по `sysexits.h`: таким кодом обработчик сам не отвечает, и поломку
не спутать с ответом. Бросок обработчика уходит в поток ошибок со стеком:

```
команда probe сломалась: app/console.lua:41: attempt to index a nil value
stack traceback:
        app/console.lua:41: in function <app/console.lua:38>
        …
```

### Справка и отказ разбора

```sh
$ tarantool console.lua --help
Вызов: console.lua [-h] <команда> ...

Команды приложения

Ключи:
   -h, --help            показать эту справку и выйти

Команды:
   cache:clear           Забыть записи кэша
   diagnose              Назвать испорченные файлы
$ tarantool console.lua cache:clear -h
Вызов: console.lua cache:clear [-h] [-f] [--older <older>]
       [--tag <tag>] [<store>]

Забыть записи кэша
Без ключа --force спрашивает подтверждение словом.

Аргументы:
   store                 хранилище (по умолчанию: default)

Ключи:
   -h, --help            показать эту справку и выйти
   -f, --force           без слова подтверждения
   --older <older>       старше, с
   --tag <tag>           метка; можно несколько раз
```

Справка — в поток вывода и код 0. Отказ разбора — в поток ошибок: строка
вызова той команды, которую набрали, и отказ; код 2. Без команды —
справка приложения и отказ «не названа команда»: вызов, который ничего
не сделал, не должен выглядеть удачей. Ключ `--help`, набранный раньше
ошибки, справку даёт: оператор просил справку, а не отказ.

```
Ошибка: команды «cache:clean» нет
может быть, «cache:clear»?
```

Отказы разбора по-русски — перевод текста рока по образцам целых
предложений. Выпуск рока закреплён (`argparse == 0.7.2-1`), и каждое
предложение сверено проверкой: новое предложение нового выпуска покажет
отказ проверки, а не английский текст у оператора. Незнакомое предложение
отдаётся как есть.

### Вызов из кода: `call`

```lua
local result, err = app:call({ 'cache:clear', '-f' })
--> { code = 0, stdout = 'хранилище default: забыто, меток 0\n', stderr = '' }

result, err = app:call({ 'cache:clear' })
--> nil, вызов console.lua кончился с кодом 1
--  err.kind = 'exit', err.code = 1, err.stdout = '', err.stderr = 'нужен ключ --force: …\n'
```

Тот же разбор, тот же обработчик и тот же код, а вывод — в строки итога.
Всякий код, кроме 0, — отказ парой, тот же, что у команды отдельным
процессом: `kind = 'exit'`, код, вывод и поток ошибок в полях. Так
проверяют команды приложения и зовут одну команду из другой.

`call` не завершает процесс и не пишет в потоки процесса, поэтому годится
и на узле. Но обработчик идёт в файбере вызывающего: долгая работа без
уступки держит узел — такую команду зовут `execute`.

### Команда на узле: `remote` и `reply`

Команде, которой нужен живой узел, — наполнить базу через службы
контейнера, показать состояние схемы из спейсов, — отдельный процесс
не поможет: у него нет ни спейсов, ни служб. Выполняет её узел —
функцией, которую зовут по iproto, — а сценарий оператора повторяет
вывод и код выхода у себя.

На узле функция отдаёт итог `reply` — одной таблицей при любом коде:

```lua
rawset(_G, 'app_command', function(argv)
    return app:reply(argv)
end)

app:reply({ 'cache:clear' })
--> { code = 1, stdout = '', stderr = 'нужен ключ --force: записи забываются насовсем\n' }
```

Отказ `call` для этого не годится: iproto донесёт его поля, но
метатаблицу потеряет, а сценарию на той стороне нужен один вид ответа.
Учётке оператора выдаётся право только на эту функцию:

```yaml
credentials:
  users:
    operator:
      password: '{{ context.operator_password }}'
      privileges:
        - permissions: [execute]
          lua_call: [app_command]
```

У оператора — сценарий на `remote`:

```lua
-- console.lua
local env = require('tnt.env')

require('tnt.console').remote({
    uri = env('CONSOLE_URI', '127.0.0.1:3301'),
    user = 'operator',
    password = env('CONSOLE_PASSWORD'),
    call = 'app_command',
}):main()
```

Адрес и пароль — окружением, а не аргументами: аргументы целиком уходят
командой на узел, а пароль в списке процессов показываться не должен.
Окружение здесь читает [`tnt-env`](https://github.com/tnt-skein/tnt-env);
зависимостью пакета он не служит, и годится обычный `os.getenv`.

```sh
$ tarantool console.lua cache:clear -f
хранилище default: забыто, меток 0
$ echo $?
0
$ tarantool console.lua cache:clear
нужен ключ --force: записи забываются насовсем
$ echo $?
1
$ CONSOLE_PASSWORD=не-тот tarantool console.lua cache:clear -f
нет ответа узла 127.0.0.1:3301: User not found or supplied credentials are invalid
$ echo $?
69
```

| Настройка | Что задаёт |
|---|---|
| `uri` | адрес iproto узла; обязателен |
| `call` | имя функции узла, которая зовёт `reply`; обязательно |
| `user`, `password` | учётка; без неё — гость |
| `timeout` | срок соединения и срок ответа, секунды, каждому; по умолчанию 60 |

Вывод узла уходит в потоки процесса как есть, код выхода — тот, которым
команда кончилась на узле. Свои коды у `remote` два:

- **69, `console.UNAVAILABLE`** — узел не ответил: нет связи, адрес
  не разобран, пароль не тот, нет права на функцию либо её нет, срок
  вышел. Причина — текст `net.box` в поток ошибок:
  `нет ответа узла 127.0.0.1:3301: Execute access to function
  'app_command' is denied for user 'operator'`. Это «служба недоступна»
  по `sysexits.h`: сценарий отличает его от отказа самой команды.
- **70, `console.BROKEN`** — узел ответил не итогом команды: функция
  узла вернула не таблицу `{ code, stdout, stderr }`, лишний ключ либо
  код не из 0…255. Это чинят в коде, а не повтором:
  `узел 127.0.0.1:3301 ответил не итогом команды: ответ узла — таблица,
  а не nil`.

Адрес в тексте отказа — без пароля, даже если его вписали в адрес
(`operator:secret@host:port` показан `operator@host:port`); пароль
держит замыкание соединения, а не поле, и команду, обойдённую `pairs`,
видно без него. Незнакомый ключ, пустой `uri` или `call`, срок не больше
нуля — бросок на строке вызывающего.

### Вывод

```lua
out:line('готово')                                -- строка в поток вывода
out:line('файлов: %d, испорченных: %d', 3, 0)     -- образец string.format
out:line('100%')                                  -- без аргументов текст не проходит format
out:line()                                        -- пустая строка
out:error('внимание: узел не отвечает')            -- строка в поток ошибок
out:describe({ id = 7, password = 'hunter2' }, { inline = true })
--> { id = 7, password = [скрыто] }
out:table({ 'файл', 'записей' }, {
    { '00000000000000000000.xlog', 80 },
    { 'журнал', '' },
})
--> файл                       записей
--> -------------------------  -------
--> 00000000000000000000.xlog  80
--> журнал
```

- **Поток ошибок** — для того, что человек должен увидеть, даже когда вывод
  уходит в файл или в разбор другой программой. То, что команда отвечает, —
  в поток вывода.
- **Таблица** выравнивает столбцы по знакам UTF-8; текст не в UTF-8 меряется
  байтами. Черта под шапкой — во всю ширину столбца, хвостовые пробелы
  срезаны. Ячейка проходит `tostring`, а строка таблицы — список и кончается
  на первой пустоте: пустую ячейку пишут `''`.
- **Показ значения** — `describe` из `tnt-debug` с его настройками
  (`inline`, `depth`, `items`, `length`): ключи в постоянном порядке, род
  значения виден, тайны под отметкой, функция и кольцо не роняют вывод.

### Команда отдельным процессом: `execute`

```lua
local result, err = console.execute('console.lua', { 'cache:clear', 'sessions', '-f' }, {
    timeout = 600,     -- срок всего запуска; по умолчанию 60 с
    input = nil,       -- что подать на вход
    env = nil,         -- окружение целиком; по умолчанию — окружение узла
    max_output = nil,  -- предел каждого потока вывода; по умолчанию 16 МиБ
})
--> { code = 0, stdout = 'хранилище sessions: забыто, меток 0\n', stderr = '' }
```

Процесс — тот же Tarantool, что у вызывающего (`arg[-1]`): другой выпуск
по `PATH` читал бы тот же код по-другому. Итог и отказ — `tnt-process`
как есть: код 0 — итог, всякий другой код — отказ `exit` с кодом, выводом
и потоком ошибок; срок вышел — отказ `timeout`, процесс убит с группой.

```lua
local _, err = console.execute('console.lua', { 'cache:clean' }, { timeout = 60 })

if err ~= nil and err.kind == 'exit' and err.code == console.USAGE then
    -- команду набрали неверно: в err.stderr строка вызова и отказ
end
```

Настройки — те же, что у `process.run`, и незнакомый ключ — бросок
на строке вызывающего. Путь сценария — от каталога узла, если не от корня.

## Что рок делает не так

Сверено на `argparse` 0.7.2 и Tarantool 3.8.0. Каждый пункт закрыт
в пакете и закреплён проверкой.

| Что | Как у рока | Как в пакете |
|---|---|---|
| ключ `--help` | печатает справку и зовёт `os.exit(0)` посреди разбора | свой ключ справки только отмечает, чью справку просили |
| ошибка разбора у `parse` | пишет в `io.stderr` и зовёт `os.exit(1)` | разбор через `pparse`, отказ — итог вызова |
| слова | по-английски, зашиты в код | отказы и строка вызова переведены, подписи групп и умолчаний — свои |
| умолчание необязательного позиционного аргумента (`args('?')`) | теряется: аргумент без значения приходит `nil` | умолчание подставляет пакет — и аргументу, и ключу |
| объект разбора | заполняется на ходу; два файбера на одном объекте мешали бы друг другу | разбор собирается заново на каждый вызов |

Потерю умолчания видно и без пакета — на одном роке:

```lua
local argparse = require('argparse')
local parser = argparse('app')

parser:argument('input')
parser:argument('output'):args('?'):default('out.txt')
parser:option('--level'):default('info')

local args = parser:parse({ 'in.txt' })
print(args.output, args.level)     --> nil     info
```

## Чем пришлось поступиться

- **Вопросов нет.** Ни «продолжить? [y/N]», ни пароля с терминала: всё,
  что нужно команде, приходит аргументами и ключами. Команда идёт
  одинаково из сценария, по расписанию и у человека, а опасное действие
  подтверждается словом — аргументом, который заранее назвала команда
  оценки. Чтение терминала к тому же ждёт в потоке событий и держит все
  файберы процесса.
- **Цвета нет.** Вывод команды уходит и в терминал, и в файл, и в разбор
  другой программой; управляющие знаки цвета там — мусор.
- **Значение со знаком минус — после `--`.** Рок читает `-5` как ключ `-5`
  и отказывает «ключа «-5» нет»; после `--` ключей нет, и `-- -5` —
  значение.
- **Повтор ключа без `many` — последнее значение.** `--older 1 --older 2`
  дают 2 без отказа: так устроен рок, и так ведут себя утилиты оболочки.
- **Число, возвращённое обработчиком, — код выхода.** `return #rows`
  в конце обработчика сделает код числом строк; хочешь удачу — не
  возвращай ничего.
- **`number` читает то же, что `tonumber`**: `0x10` — 16, `1e3` — 1000,
  пробелы по краям пропускаются.
- **Справка ключа с двумя именами — в две строки.** Так её раскладывает
  рок, и своя раскладка справки была бы вторым разбором объявления.
- **Разбор собирается заново на каждый вызов.** Это таблица на команду
  и элемент, и `call` целиком — сборка, разбор, обработчик и вывод —
  стоит около 0,1 мс (замер: 114 мкс на приложении из двух команд).
  Платится это за то, что общего объекта разбора у файберов нет.
- **Команда на узле идёт в файбере iproto узла.** Функция узла зовёт
  `reply`, как `call`: долгая работа без уступки держит узел, и такую
  команду узел запускает отдельным процессом сам (`execute`).
- **Срок вышел — узел не остановлен.** `remote` перестаёт ждать и
  кончается кодом 69, а команда на узле доходит до конца: iproto
  не отменяет начатый вызов. Повтор команды, которая пишет, должен быть
  безопасен — наполнители, например, кладут записи заменой.
- **Командная строка — только строки.** Функция узла получает список
  строк, как `run`: ни таблиц, ни чисел сценарий на узел не шлёт.
- **Вывод в потоки процесса ждёт.** `run` и `main` пишут в `io.stdout`,
  а запись в терминал или трубу держит поток событий. Для процесса
  командной строки это не беда; на узле команду зовут `call` — вывод
  в строки — либо `execute`.

## Проверки

Проверки лежат в `test/` и разбирают **настоящим роком**: пакет — слой
над ним, и двойник рока проверял бы, что мы правильно разговариваем сами
с собой. Команда на узле проверяется на настоящем узле: функция на `reply`
из исходников пакета, учётка с правом только на неё, отказы соединения,
права и срока — текстами `net.box`; двойник `net.box` проверяет только
проводку — что ушло в соединение и что оно закрыто. Отказы и справка
сверяются дословно с тем, что отдаёт закреплённый выпуск. Вывод в потоки
процесса, аргументы процесса и выход проверяет ребёнок — сценарий
отдельным Tarantool с исходниками пакета, позванный `execute`; в процессе
проверок подменяются только они:

```lua
console._set_source({

    end,

app:main()   -- процесс не кончается, код — в exited

```
